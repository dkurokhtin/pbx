# pbx scan — авто-заполнение реестра проектов

- **Дата:** 2026-07-01
- **Статус:** дизайн утверждён, ожидает плана реализации
- **Файл-цель:** `pbx`
- **Предпосылка:** реестр `$PBX_REGISTRY_DIR/<имя>.conf` (пер-машинный: `SRC` на пакующей машине, `REPO` на доставляющей). См. фичи «реестр проектов».

## Проблема

Реестр заполняется вручную (`pbx add` по одному проекту). На доставляющей машине (рабочий ноут,
`/root`) это утомительно: `pbx list` показывает только заведённые записи. Нужна команда, которая
сама находит репозитории в каталоге и создаёт записи реестра. Сложность — «контейнер-репо»: папка
сама git-репо без remote, а реальный репо лежит в подпапке (напр. `/root/vnd` пуст, фронт в
`/root/vnd/vnd_frontend`); наивный скан зарегистрировал бы контейнер и сломал бы доставку.

## Решение

Команда `pbx scan (--repo|--src) [каталог]` — обходит подпапки каталога, определяет реальные
git-репозитории (по наличию remote) и создаёт записи реестра.

### Вызов и выбор поля

- Ровно один флаг обязателен:
  - `--repo` → в запись пишется `REPO=<путь>` (доставляющая машина);
  - `--src`  → в запись пишется `SRC=<путь>` (пакующая машина).
- `[каталог]` необязателен; по умолчанию: `--repo` → `$PROJECTS_ROOT` (`/root`), `--src` → `$WORKSPACE`.
- Ни одного/оба флага, или неизвестный каталог → `die` с подсказкой по использованию.

### Алгоритм обхода (глубина спуска — 1 уровень)

Для каждой непосредственной подпапки `D` каталога:

1. `D` — git-репо **с remote** (`[[ -d "$D/.git" ]]` и `git -C "$D" remote` непусто) →
   кандидат: имя = `basename D`, путь = `D`.
2. `D` — git-репо **без remote** (контейнер) → перебрать подпапки `D/*/`, оставить те, что
   git-репо с remote:
   - ровно одна → кандидат: имя = `basename D`, путь = эта внутренняя папка
     (`vnd` → `/root/vnd/vnd_frontend`);
   - ноль → пропуск;
   - несколько → пропуск + предупреждение (перечислить кандидатов).
3. `D` — не git-репо → пропуск.

### Запись реестра

- Для каждого кандидата — файл `$PBX_REGISTRY_DIR/<имя>.conf` (каталог создаётся при необходимости):
  - строка `REPO=<путь>` или `SRC=<путь>` (по флагу);
  - определить хост remote (`origin`, иначе первый remote); если содержит `github.com` →
    дописать `FORGE=github` (для gitlab — дефолт, не пишем).
- Если `<имя>.conf` **уже существует** — не перезаписывать, пометить «пропущено (уже есть)».
- `--dry-run` — печатать, что было бы создано/пропущено, ничего не писать.

### Вывод

Построчно по каждому проекту: `создан`/`пропущен (есть)`/`пропущен (контейнер неоднозначен)`.
В конце сводка: `создано N, пропущено M, предупреждений K`.

## Ограничения / границы

- `scan` только заполняет реестр — ничего не пакует/доставляет.
- Спуск в контейнер — на 1 уровень (`D/*/`), глубже не идём.
- Не-git подпапки и служебные (`_*`, `.*`) пропускаются.
- Существующие записи не трогаются (без флага перезаписи — YAGNI; правка вручную).
- `set -euo pipefail` сохранён; функция set-e/set-u-безопасна; сообщения на русском; без новых
  внешних зависимостей (только `git`, coreutils).

## Критерии приёмки

1. `pbx scan` без `--repo`/`--src` (или с обоими) → `die` с подсказкой; неизвестный каталог → `die`.
2. `pbx scan --repo <dir>` для подпапки-репо с remote создаёт `<имя>.conf` с `REPO=<dir>/<имя>`.
3. Контейнер (git без remote) с ровно одним внутренним репо-с-remote → запись под именем внешней
   папки, путь = внутренний репо.
4. Контейнер с несколькими внутренними репо-с-remote → пропуск + предупреждение, файл не создан.
5. Подпапка без `.git` или без remote (и не контейнер) → пропуск.
6. Существующий `<имя>.conf` не перезаписывается (помечен «пропущено»).
7. Remote на `github.com` → в запись добавлена `FORGE=github`; на gitlab — не добавлена.
8. `--dry-run` не создаёт/не меняет ни одного файла, но печатает план.
9. `--src` пишет `SRC=…` вместо `REPO=…`; дефолтный каталог — `$WORKSPACE`.
10. `set -euo pipefail` сохранён; легаси не тронуты; `pbx list` после `scan` показывает новые проекты.
