# pbx v2 — визуальный апгрейд + интерактивное меню (дизайн)

Дата: 2026-07-02. Статус: одобрен пользователем (подход A + гейт цвета).

## 1. Контекст и цель

`pbx` — один самодостаточный bash-файл (~600 строк), CLI доставки проектов между
двумя машинами (дом WSL → рабочий ноут `/root`, gitlab). Перенос на ноут — ручное
копирование одного файла. Философия из README: «без зависимостей — только git,
tar, rsync и bash».

Цель работы:
1. Заметно улучшить визуал вывода всех команд.
2. Вызов голого `pbx` в интерактивном терминале открывает меню-список со
   стрелками: действие → проект → параметры → выполнение существующей команды.

Обе машины: bash ≥ 5, есть Node ≥ 18 (не используется — см. §3). Нет gum/fzf/dialog/jq.

## 2. Ключевое требование и инварианты

**Один файл.** Результат остаётся одним bash-файлом; перенос — копирование.

**Машиночитаемые поверхности неприкосновенны.** `pbx` активно вызывают ИИ-агенты
неинтерактивно и парсят вывод. Не меняются:
- эмодзи-маркеры `✅ ❌ 🔵 ⚠️ 🧭 📋` и тексты сообщений;
- формат `collect_diag` (блоки `[pbx] [env] [config] [repo] [archive]`) и лог-файлы;
- fail-closed deliver-guard при non-TTY (без `--yes`/`PBX_ASSUME_YES` — die);
- существующий контракт `_tests/test_pbx.sh` (source-ит скрипт, дёргает функции).

Особый случай: `pbx list` в пайпе получает **стабильный machine-readable формат**
(голые имена по строке) — это осознанное изменение сегодняшнего `  • имя`, см. §7.

**Байтовый инвариант plain-режима.** При non-TTY/`NO_COLOR`/`TERM=dumb` вывод
байт-в-байт равен сегодняшнему тексту **минус ANSI-коды**. (Сейчас коды льются
безусловно даже в пайп; их исчезновение из редиректов — одобренное изменение.)

## 3. Решение и отвергнутые альтернативы

Принят **подход A: всё в чистом bash внутри того же файла**.

Отвергнуто (по результатам проработки тремя независимыми агентами):
- **B. Полный переезд на Node (esbuild-бандл в один файл).** Цена: переписывание
  ~600 строк battle-tested логики и 699 строк тестов с нуля, потеря `set -e` как
  сетки безопасности (десяток spawnSync в deliver), риск регрессий в
  deliver-guard (инцидент SUP-2603), минифицированный бандл нечитаем в git diff,
  bash всё равно остаётся рантайм-зависимостью (конфиги реестра — bash-синтаксис).
  Эмпирика: ink не собирается в один CJS-файл вовсе; @clack/prompts — 24 КБ, но
  выигрыш не окупает двойное переписывание ради меню из 8 пунктов.
- **C. Гибрид: bash-ядро + JS-heredoc-меню в том же файле.** Постоянный налог:
  двуязычный файл (shellcheck/подсветка слепы к JS), непокрытый тестами JS-блоб,
  протокол bash↔node (NUL-argv, самодельный JSON-эскейпер), риск дрейфа меню от
  сигнатур `cmd_*`. Единственный выигрыш — эргономика написания ~100 строк
  перерисовки, которые пишутся один раз.
- Честный вывод исследования: для статического визуала Node не даёт ничего —
  bash шлёт те же ANSI-коды. Node выигрывает только в удобстве написания
  интерактивной перерисовки.

## 4. Архитектура файла

- Вся новизна — в размеченной секции `# ===== UI: палитра, глифы, меню =====`
  в конце файла (перед `main`). Первые ~600 строк бизнес-логики остаются
  компактными и читаются отдельно.
- `main()`: argv пуст → `cmd_menu` при полном TTY-гейте (§6), иначе `cmd_help`
  (текущее поведение). Явные команды (`pbx pack sup`) меню не проходят.
- Ожидаемый размер: ~1000 строк (+400).
- Никакого интерактивного кода на top-level: только внутри функций, вызываемых
  из `main()` (инвариант для source-инга тестами).

## 5. Палитра и детект возможностей

Однократно при старте (top-level присваивания, без побочных эффектов):

```bash
UI_COLOR_OUT=0  # -t 1 && -z NO_COLOR && TERM != dumb
UI_COLOR_ERR=0  # -t 2 && -z NO_COLOR && TERM != dumb   (c_red/c_warn пишут в stderr)
UI_TTY=0        # -t 0 && -t 1
UI_UTF8=0       # locale charmap == UTF-8
```

- Палитра: текущие 4 цвета + `C_BOLD C_DIM C_CYAN C_GREY` (+`C_RESET`).
  При выключенном гейте соответствующие `C_*` — пустые строки, поэтому все
  printf-шаблоны едины для обоих режимов.
- `c_blue/c_green/c_red/c_warn` переводятся на `C_*`-переменные: сигнатуры,
  тексты и потоки (stdout/stderr) не меняются — только условность окраски.
  stdout-функции красят по `UI_COLOR_OUT`, stderr-функции — по `UI_COLOR_ERR`.
- Глифы: `▸ │ ├ └ ✓ ✗` при `UI_UTF8=1`, иначе ASCII `> | + + * x`.
  Глиф-переменные (`G_PTR G_BAR ...`) — та же схема, что `C_*`.

## 6. Интерактивное меню

**Гейт запуска:** argv пуст ∧ `-t 0` ∧ `-t 1` ∧ `TERM` ∉ {dumb, unknown, ""} ∧
`-z PBX_NO_MENU`. Иначе — `cmd_help`, как сегодня. `PBX_NO_MENU=1` — вечный
рубильник для автоматизации и отладки.

**Экраны:**
1. Действие: pack / deliver / log / list / scan / add / help / выход.
2. Проект: массив из `list_projects` (единый источник истины) — для
   pack/deliver/log. `scan`/`add` в v1 подсказывают CLI-синтаксис и выходят
   (аргументы у них разнородные; экранная форма — вне скоупа).
3. Параметры deliver: ветка через `read -e -i "feature/"` (fallback на голый
   `read -r`, если readline недоступен), сообщение коммита через `read -r`.
   Мягкая валидация конвенции ветки на этапе ввода (предупреждение, не блок).
4. Предпросмотр собранной команды (dim) → вызов существующей `cmd_*` as-is.

Deliver-guard остаётся внутри `cmd_deliver` — меню его не дублирует и не
обходит; `--yes` из меню не передаётся никогда.

**После команды:** «читающие» (list/log/help) — Enter → возврат в меню;
«пишущие» (pack/deliver/scan/add) — выход (человек читает результат).

**`menu_select <title> <opt...>` — механика:**
- Возврат: индекс в stdout; rc=130 — отмена (Esc/q/Ctrl+C/EOF).
- **Вся отрисовка — в stderr**; в stdout — только финальный индекс (иначе
  command substitution съест кадры перерисовки).
- Raw-режим: `UI_STTY_SAVED=$(stty -g)` → `stty -echo -icanon min 1 time 0`;
  спрятать курсор. Любой сбой `stty` → немедленный fallback.
- Клавиши: `↑/↓` (оба варианта: `ESC[A/B` и `ESCOA/B`), `j/k`, цифры `1–9` —
  прыжок+подтверждение, Enter — выбор, Esc/q — отмена. Разбор ESC-последовательности
  с таймаутом (`read -rsn1 -t 0.05` на хвост): голый Esc отличим от стрелки.
- Перерисовка: курсор вверх на N строк + перерисовать блок. Без alternate screen.
- Уборка: `trap 'ui_raw_off' EXIT INT TERM` на время меню (restore stty, показать
  курсор); после выхода из меню trap снимается/восстанавливается прежний.
  Терминал не остаётся сломанным ни при каком сбое. Не конфликтует с
  `trap ... RETURN` в `cmd_deliver` (другой сигнал, другая область).
- `set -euo pipefail`-дисциплина: `read` с rc≠0 всегда в форме `read ... || ...`;
  инкременты только `i=$((i+1))` (не `((i++))`).

**`menu_select_plain`** — fallback: нумерованный список + `read -r -p`. Используется
при сбое raw-режима; отдельно тестируем подачей ввода пайпом.

## 7. Рестайл вывода команд (TTY-режим)

Plain-режим каждой команды = сегодняшний текст (§2). TTY-режим:

- **Секции:** `ui_section` — `▸ <заголовок>` (bold+blue) + dim-линейка на ширину
  ≤78. Заменяет голые `🔵 ...`-строки в TTY; в plain печатает ровно `🔵 <текст>`.
- **key-value:** `ui_kv` — выровненные пары (`SRC → …`, `REPO → …`) для эха
  конфигурации в pack/deliver.
- **pack:** секция + итог `✅ Архив готов: <путь>` + dim-строка с размером (`du -h`).
- **deliver-guard** (главное место): секция-заголовок; diffstat как есть;
  удаления — отдельным блоком: красный заголовок со счётчиком
  («будут удалены N файлов») + список; bold-промпт `[y/N]`. Тексты сообщений —
  сегодняшние (протокол агентов), меняется только оформление вокруг.
- **Итог deliver:** трёхстрочный блок `│ ├ └` — ветка / MR-цель / сообщение.
  Полноширинных рамок нет нигде (хрупки к ширине терминала и wrap).
- **list (TTY):** выровненная таблица «имя · SRC ✓/✗ · архив (возраст/—)».
  Git-статус репо не дёргаем (медленно на /mnt/c). **list (пайп):** голые имена
  по строке — это упрощение сегодняшнего `  • имя` до чистого machine-readable
  формата (единственное осознанное изменение plain-текста; `pbx_deliver_reminder`
  и тесты проверить/поправить).
- **help:** группировка команд, dim-комментарии, подсветка примеров; в plain —
  сегодняшний heredoc.
- **scan/add/log:** секции + существующие строки; `collect_diag` не трогаем вовсе.

## 8. Чего НЕ делаем (v1)

- Спиннеры/прогресс: git сам показывает прогресс push/pull; tar/rsync локально
  быстрые; фоновый процесс под `set -euo pipefail` — лишний класс рисков.
- Полноэкранный дашборд, alternate screen, fuzzy-фильтр — возможная эволюция.
- Экранные формы для scan/add.
- Node/gum/whiptail/fzf — любые внешние зависимости.

## 9. Тестирование (TDD, расширение `_tests/test_pbx.sh`)

Существующие тесты проходят без правок: они source-ят скрипт и работают в
non-TTY → получают plain-режим (кроме проверок, завязанных на ANSI-коды или на
формат `pbx list` — эти обновить осознанно).

Новые тесты:
1. Гейт цвета: вывод в пайп не содержит `\033[` ни на stdout, ни на stderr.
2. Байтовый инвариант: plain-вывод pack/deliver-guard/list идентичен эталону.
3. Гейт меню: `pbx </dev/null` → help, завершение без зависания; логика гейта
   `PBX_NO_MENU` — через `source pbx` + подмену `UI_TTY=1` и проверку выбранной
   ветки диспетчера (raw-TTY в CI не эмулируем).
4. `menu_select_plain`: выбор и отмена подачей ввода пайпом.
5. ASCII-fallback: при не-UTF8 локали в выводе нет `▸│├└✓`.
6. Топ-левел чистота: `source pbx` не запускает интерактив и ничего не печатает.

Ручная проверка меню (raw-режим не эмулируется без pty): Windows Terminal,
VS Code terminal, ssh на ноут; чек-лист в PR.

## 10. Карта рисков → закрытие в дизайне

| Риск | Закрытие |
|---|---|
| Агент/скрипт зависает на меню (stdin не TTY) | гейт `-t 0 ∧ -t 1` + тест №3; fail-closed guard не тронут |
| Разные ESC-коды стрелок (WT/VS Code/ssh/tmux) | оба варианта кодов + j/k + цифры; таймаут-разбор ESC; fallback plain-меню |
| Сломанный терминал после сбоя в raw | `stty -g` save/restore + trap EXIT/INT/TERM + показ курсора |
| `set -e` × `read`/арифметика | дисциплина `|| ...` и `i=$((i+1))`; комментарии-предупреждения в секции UI |
| Кракозябры в не-UTF8 консолях | `UI_UTF8`-детект + ASCII-глифы (тест №5) |
| ANSI в логах/пайпах агентов | гейт цвета `UI_COLOR_OUT/ERR` (тест №1) |
| Слом парсинга `pbx list` потребителями | пайп-формат — голые имена; аудит `pbx_deliver_reminder.py` и тестов |
| Слом source-инга тестами | никакого интерактива на top-level (тест №6) |
| Конфликт trap-ов с `cmd_deliver` | RETURN-trap локален; меню использует EXIT/INT/TERM с восстановлением |

## 11. Критерии приёмки

1. `pbx` в терминале → меню; стрелки/j·k/цифры/Enter/Esc работают; Ctrl+C не
   ломает терминал.
2. Меню-путь deliver проходит через полный guard с подтверждением.
3. `pbx pack sup`, `pbx deliver ... --yes` из агента — вывод и коды возврата
   как раньше (минус ANSI в редиректах).
4. Все тесты `_tests/test_pbx.sh` зелёные, включая новые.
5. Файл остаётся одним bash-скриптом; перенос на ноут — копирование.
6. README обновлён (демо-SVG перезаписать новым видом — отдельным шагом).

2. Рестайл вывода команд (pack → deliver/guard → list → help → итоги).
3. `menu_select` + raw-обвязка + `menu_select_plain` (+ тесты №3, 4).
4. Экраны меню (действие → проект → параметры → вызов `cmd_*`).
