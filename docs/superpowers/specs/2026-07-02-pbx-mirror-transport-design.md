# pbx Э2 — git-транспорт через личные GitHub-зеркала (дизайн)

Дата: 2026-07-02. Статус: спроектирован автономно по одобренной декомпозиции
(«давай к следующему шагу»); решения приняты мной, допущения помечены (§2.1) —
пользователь может скорректировать любое до/после реализации.

## 1. Контекст и цель

Этап Э2 дорожной карты (Э1 status ✓ → **Э2 транспорт** → Э3 обратный поток →
Э4 ctx). Заменяет ручной перенос архива: дом пушит снапшот рабочего дерева
веткой в личное GitHub-зеркало, ноут доставляет из зеркала в корп-gitlab тем
же battle-tested deliver-путём. Архивный путь остаётся как fallback.

Факты разведки (2026-07-02, эмпирически):
- Зеркала УЖЕ существуют (все private): dkurokhtin/{vnd, rbp, SUP,
  bot-support-cleaning, pbx}. Нет зеркал: suba (пустой git без коммитов),
  smartapp-parking (не git).
- Дом: SSH-auth к GitHub работает; SRC vnd/rbp уже смотрят remote-ами в зеркала.
- Ноут: GitHub доступен и под VPN; у root нет ключа → HTTPS+PAT (см. §6).
- Обе механики (push-снапшот и deliver-из-зеркала) проверены research-агентами
  вживую на /tmp-фикстурах, включая гонки и потерю данных в отвергнутых
  вариантах. Найденные грабли зафиксированы в §4–5.

## 2. Решения

- **MIRROR=<git-url>** — новый ключ реестра проекта (свой на каждой машине,
  как SRC/REPO). Нет MIRROR → push/deliver--mirror дают понятную ошибку.
- **Дом: `pbx push <проект> [ветка]`** — снапшот рабочего дерева SRC
  (staged+unstaged+untracked, минус excludes) уезжает коммитом в ветку зеркала.
  Ветка по умолчанию — текущая ветка SRC.
- **Ноут: `pbx deliver <проект> <ветка> <сообщение> --mirror`** — явный флаг
  (в любой позиции, как --yes): источник — ветка зеркала вместо архива.
  Автодетекта нет: доставка в корп-gitlab не должна менять источник «сюрпризом».
- **Отдельной команды `pbx fetch` нет** (YAGNI): deliver --mirror фетчит сам.
- **Меню**: пункт `push` после `pack` (см. §7).
- Сетевые вызовы: всегда `GIT_TERMINAL_PROMPT=0` (не зависать на промпте
  логина), таймаут не нужен — git сам падает быстро при недоступности.

### 2.1 Допущения (пользователь отсутствовал — скорректировать при желании)

1. Имя снапшот-ветки в зеркале = как передали (обычно feature/<тикет>-<slug>),
   без служебного неймспейса.
2. suba/smartapp-parking — вне охвата Э2 (зеркал нет; завести — руками или Э3).
3. Реальные MIRROR-записи добавляются в ДОМАШНИЙ реестр в финальном таске
   (vnd→dkurokhtin/vnd, rbp→dkurokhtin/rbp, sup→dkurokhtin/SUP); реестр ноута
   пользователь заполняет сам при переносе pbx.
4. Снапшот УВАЖАЕТ .gitignore SRC — осознанное отличие от pack (tar тащил
   gitignored-файлы, не входящие в фикс-список excludes, например .env;
   в git-ветку личного зеркала секретам уезжать нельзя). Задокументировано
   в README как различие путей.

## 3. Реестр и конфиг

`MIRROR=` читается load_config-ом как обычный ключ (слои те же). В `pbx add` —
закомментированная подсказка `# MIRROR=git@github.com:<user>/<repo>.git`.

## 4. `pbx push` — механика снапшота (проверено вживую)

Ядро: **теневой индекс** — SRC (HEAD/index/staging/stash) не трогается нигде.

1. `GIT_INDEX_FILE=$(mktemp)` → **немедленный `rm -f`** (грабля: существующий
   пустой файл → fatal «index file smaller than expected»).
2. Засеять теневой индекс **копией реального** `.git/index` (грабля: с пустым
   индексом файл, закоммиченный до появления его паттерна в .gitignore,
   с незакоммиченной правкой — молча теряет правку; с копией — обновляется,
   как в реальном git).
3. `git add -A` с pathspec-исключениями из **существующей `pack_exclude_args()`**
   (единственный источник истины), транслированными хелпером
   `pack_exclude_pathspecs()`. Грабли git-pathspec (обе пойманы вживую):
   - короткая форма `:!имя` падает fatal-ом на именах с ведущим `_`
     (`__pycache__`: «Unimplemented pathspec magic '_'») → только длинная
     `:(glob,exclude)…`;
   - без глоба матч только на верхнем уровне (не как tar) → обе формы:
     `**/имя` и `**/имя/**` (иначе вложенные node_modules утекут гигабайтами).
4. `git write-tree` → `git commit-tree` с **parent-chain**: родители =
   [текущий tip ветки зеркала (через `git fetch <MIRROR> <ветка>` → FETCH_HEAD,
   без постоянных ref-ов в SRC), SRC HEAD (provenance)]. Сообщение:
   `pbx push: снапшот <SRC-ветка> @ <sha7>`.
5. **Валидация SHA** (`^[0-9a-f]{40}$`) перед push — грабля поймана вживую:
   `git push mirror "":refs/heads/<ветка>` с пустой переменной — это синтаксис
   УДАЛЕНИЯ ветки на remote (дважды снёс тестовую ветку при отладке).
6. `git push <MIRROR> <sha>:refs/heads/<ветка>` — **без --force**: благодаря
   parent-chain push всегда fast-forward; гонка (кто-то подвинул ветку между
   fetch и push) → штатный отказ git → bounded retry (3 попытки, перечитывая
   tip). Эмпирика: смоделированная гонка не потеряла чужой коммит ни разу.

Вывод команды: секция «Push <проект>», kv MIRROR/BRANCH, итог ✅ со sha7.
Пустой снапшот (дерево == tip зеркала) → «изменений нет» без пуша.

## 5. `deliver --mirror` — механика (вариант В; проверено вживую)

**Принят вариант В**: `git fetch <MIRROR> <ветка>` → tmp-каталог →
`git archive FETCH_HEAD | tar -x` → далее **существующий** deliver-путь
(rsync -a --delete с sync-excludes → ветка от BASE → git add -A → **guard**
→ commit → forge_push). Диф к cmd_deliver минимален: только способ наполнения
tmp; rsync-ядро, guard, trap, коды возврата — нетронуты.

Отвергнуты (оба проверены вживую — НЕ «упрощать» к ним в будущем):
- **А** (`git rm -r --cached` + `checkout FETCH_HEAD -- .` + `add -A`):
  ТИХО ТЕРЯЕТ УДАЛЕНИЯ (checkout не трогает отсутствующие в целевом дереве
  файлы; add -A возвращает их в индекс; guard показывает ложно-зелёную
  картину без удаления) — класс инцидента SUP-2603, воспроизведено.
- **Б** (`read-tree -m -u`): корректен, но имеет окно, где sync-excludes
  (.gitlab-ci.yml, CLAUDE.md, секреты) физически отсутствуют на диске REPO —
  краш/Ctrl+C в этом окне оставляет их удалёнными. Вариант В структурно без
  окна: rsync --exclude вообще не рассматривает защищённые пути.

Инварианты проверки (все 6 прошли на фикстуре): удаления отражены; новые
файлы есть; sync-excludes байт-в-байт из dev; guard показывает ровно ожидаемый
diffstat; ветка чистая от BASE; незакоммиченные правки снапшота доехали.

Известный побочный эффект: rsync-предупреждение «cannot delete non-empty
directory» для каталога с excluded-файлом, отсутствующего в источнике —
безобидно (exit 0, содержимое верное); НЕ чинить исключением каталога целиком.

## 6. Auth (документация, не код)

Дом — SSH уже работает. Ноут (root) — README-раздел:
- HTTPS + fine-grained PAT (Contents: Read/Write, скоуп ТОЛЬКО на зеркала,
  срок ~90 дней) — 443 всегда открыт в корп-сети; SSH — запасной, если 22/443
  ssh.github.com не режется.
- Токен НЕ в URL реестра (светится в remote -v/логах) — только credential
  helper: `git credential-cache` (память) или `~/.git-credentials` 600
  (plaintext-риск компенсируется узким скоупом и TTL).
- pbx при отсутствии auth падает с понятной ошибкой (GIT_TERMINAL_PROMPT=0),
  а не виснет.

## 7. Меню

Пункт `push    — снапшот рабочего дерева в зеркало` после `pack`. Флоу:
выбор проекта → ветка (`read -e`, дефолт — текущая ветка SRC) → `cmd_push`.
Пишущая команда → выход из меню. «выход» становится 10-м; тесты нумерации
обновляются (deliver сдвигается на 3, log на 4, status на 5, list на 6 и т.д. —
ВСЕ меню-тесты с цифровым вводом пересматриваются).

## 9. Тестирование (TDD; ВСЕ сетевые операции — на локальных bare-репо file://)

1. `pack_exclude_pathspecs`: длинная форма, обе глоб-формы, `__pycache__` не
   роняет; вложенный node_modules исключается (фикстура с sub/node_modules).
2. `snapshot_tree`: staged+unstaged+untracked в снапшоте; CLAUDE.md/.claude
   исключены; SRC после — бит-в-бит (status/stash нетронуты); gitignored-
   tracked файл с правкой НЕ теряется (грабля №2).
3. `cmd_push` e2e на bare-зеркале: первый push создаёт ветку; второй —
   fast-forward (parent-chain); пустой снапшот → «изменений нет», без пуша;
   без MIRROR → die с подсказкой; пустой SHA невозможен (валидация).
4. deliver --mirror e2e (фикстура: bare-gitlab + bare-mirror + REPO):
   удаление/добавление/правка доехали; sync-excludes живы; guard fail-closed
   при удалениях без --yes (не ослаблен!); архивный путь без --mirror
   работает как раньше (регресс).
5. Гонка push: сымитировать чужой push между fetch и push → retry побеждает,
   чужой коммит цел.
6. Меню: обновлённая нумерация всех цифровых вводов.

## 10. Критерии приёмки

1. Дома: `pbx push vnd feature/X` создаёт/обновляет ветку в зеркале (в тестах —
   bare), SRC не тронут ни в одном аспекте.
2. deliver --mirror на фикстуре эквивалентен архивному пути по результату и
   guard-поведению.
3. Все существующие тесты зелёные (кроме осознанного обновления меню-нумерации);
   plain-инварианты не задеты.
4. Один bash-файл; README дополнен (транспорт, auth ноута, отличие .gitignore).
5. MIRROR прописан в домашнем реестре vnd/rbp/sup.

## 11. Этапы реализации (для плана)
