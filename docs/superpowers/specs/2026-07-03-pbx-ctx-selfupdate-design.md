# pbx Э4 — `pbx ctx` (вердикт дом↔корп) и `pbx self-update` (дизайн)

Дата: 2026-07-03. Статус: одобрен пользователем по секциям (охват «оба:
ctx + self-update»; подходы A «композиция живых конвейеров» и S1
«shallow-fetch + атомарная замена» — выбраны из 3 альтернатив каждый).

## 1. Контекст и цель

Финальный этап дорожной карты (Э1 status ✓ → Э2 транспорт ✓ → Э3 обратный
поток ✓ → **Э4 ctx/self-update**). После Э3 дом ВИДИТ корп-состояние
(`pbx corp`), но сравнение с домашней картиной делает человек/ИИ вручную.
Э4 закрывает две последние дыры:

- **`pbx ctx`** — автосравнение дом↔корп с вердиктом готовности к доставке.
  Страховка класса SUP-2603 (устаревший домашний снимок молча откатывает
  чужую влитую работу) срабатывает автоматически на этапе ПЛАНИРОВАНИЯ,
  а не только deliver-guard-ом в конце конвейера.
- **`pbx self-update`** — обновление pbx на ноуте из GitHub-зеркала
  `dkurokhtin/pbx` одной командой (сейчас — ручное копирование файла).

## 2. Решения

- **ctx = композиция живых конвейеров** (выбор пользователя из A/B/C):
  реюз сбора status (ST_*) + чтения снимка `pbx/state` зеркала (как corp,
  свежий fetch). Никакого локального кэша корп-состояния (отвергнут B:
  вторая копия истины) и никаких флагов у corp (отвергнут C: ломает
  устоявшийся контракт Э3).
- **ctx — агрегатор + вердикт** (выбор пользователя): сам сравнивает и
  выдаёт `ok/warn/danger/unknown` с причинами; заготовку deliver-команды
  НЕ генерирует (кандидат на потом).
- **self-update = shallow-fetch + атомарная замена** (выбор S1 из S1/S2/S3):
  та же git/auth-модель, что Э2/Э3 (дома SSH, на ноуте HTTPS+PAT из
  credential store). Отвергнуты: curl к raw (второй auth-канал, нет
  атомарной версии), доставка pbx через deliver (циклично, руками).
- **UX self-update: явная команда + тихая проверка** (выбор пользователя):
  обновление только по явному запуску; дешёвая проверка «есть свежее» —
  в конце `pbx snapshot` (сеть там точно есть), только подсказка.
- Сетевые вызовы — по стандарту проекта: `GIT_TERMINAL_PROMPT=0 timeout 30`.

## 3. `pbx ctx [проект] [--json]`

Выбор проектов — как у corp: без аргумента все с MIRROR; с аргументом один
(без MIRROR/не в реестре → die с подсказкой, как corp). Exit 0 при успешном
сборе: вердикт — в данных, сетевые сбои не фатальны (стиль corp).

### 3.1 Сбор

По каждому проекту: (1) домашняя картина — тот же сбор, что `cmd_status`
(ветка/dirty SRC, upstream ahead/behind, meta pack: COMMIT/PACKED_AT,
push-инфо: PUSH_BRANCH/PUSH_COMMIT/PUSHED_AT); (2) корп-картина —
`corp_read_state` из зеркала (meta.env: SNAPSHOT_AT/fetch_ok, base: tip
dev sha/date/subj, log.tsv 20 коммитов, branches.tsv, dirty/in_merge REPO).

### 3.2 Проверки и вердикт

Каждая проверка даёт причину `{code, level, msg}`. Вердикт проекта — худший
уровень: `danger > warn > ok`; отдельный `unknown` — сравнивать не с чем
(нет MIRROR / снимка нет / зеркало недоступно / SRC не git). Проверка при
сомнении ошибается в сторону строгости (fail-closed ДНК pbx).

| code | level | условие |
|---|---|---|
| `home_behind_corp` | danger | tip корп-dev НЕ в истории SRC, но часть корп-лога в ней есть → дом отстал на N коммитов (N = индекс первого найденного) |
| `histories_unrelated` | warn | ни один из 20 коммитов корп-лога не найден дома (отставание >20 либо несравнимые истории) |
| `snapshot_stale` | warn | снимку >24ч (порог Э3) |
| `snapshot_no_vpn` | warn | снимок сделан с `fetch_ok=false` — корп-данные в нём несвежие |
| `repo_dirty` | warn | REPO ноута грязный (dirty>0) — доставка встанет |
| `repo_in_merge` | warn | REPO ноута в незавершённом merge |
| `push_stale` | warn | есть push-мета и `PUSH_COMMIT` ≠ текущий HEAD SRC — снапшот в зеркале отстаёт от дома |
| `pack_stale` | warn | есть архив и он протух (реюз семантики `stale` Э1) |
| `undelivered_branches` | info | в корп есть ветки ahead>0 — показать списком, на вердикт не влияет |

Механика `home_behind_corp`: `git -C SRC cat-file -e <sha>^{commit}` для
tip корп-dev; не найден → перебор 20 сокращённых SHA (`%h`) корп-лога
сверху вниз, первый найденный индекс = N. Неоднозначный короткий SHA
(cat-file ошибка) трактуется как «не найден» — строгая сторона. Ни одного
из 20 → `histories_unrelated`.

### 3.3 Вывод

- **TTY**: секция с эмодзи-протоколом; по проекту — вердикт-строка
  (🟢 ok / 🟡 warn / 🔴 danger / ⚪ unknown) + причины списком.
- **non-TTY**: та же структура без ANSI (логи агентов).
- **`--json`**: массив, ручная сборка `_json_str_v2`, порядок ключей
  фиксирован (контракт для ИИ):

```json
[{"name":"vnd","verdict":"danger","behind_n":3,
  "reasons":[{"code":"home_behind_corp","level":"danger",
              "msg":"дом отстал от корп-dev на 3 коммита"}],
  "home":{"branch":"dev","dirty":13,"head":"abc1234…",
          "meta_commit":"","packed_at":1751448000,
          "push_commit":"def5678…","pushed_at":1751450000},
  "corp":{"snapshot_at":1751500000,"fetch_ok":true,
          "base_branch":"dev","base_sha":"0a1b2c3…","base_date":1751490000,
          "repo_dirty":0,"in_merge":false,
          "undelivered":[{"name":"feature/x","ahead":2}]},
  "compared_at":1751540000}]
```

Сентинели — как в status Э1: неизвестная строка `""`, неизвестное число
`-1`. `behind_n` — результат сравнения (N из `home_behind_corp`), потому
лежит в корне рядом с verdict, `-1` если неизвестно. JSON-контракты
status/corp Э1–Э3 НЕ меняются — у ctx собственная схема.

## 4. `pbx self-update [--check]`

- **Источник**: `SELF_MIRROR=` в `~/.config/pbx/self.conf` (bash KEY=value,
  как все конфиги; дома SSH-URL, на ноуте HTTPS — поэтому дефолт в код не
  зашит); env-override `PBX_SELF_MIRROR`. Нет self.conf и env → die с
  подсказкой-однострочником для создания.
- **Версия установленного**: SHA в `~/.config/pbx/self.rev`, запись через
  существующий `meta_update` (атомарно, best-effort: провал записи → warn,
  следующий запуск честно перепроверит).

Алгоритм:
1. `realpath $0`; скрипт в git-workspace репо pbx (рядом `.git`) → die
   «это рабочая копия — обновляйся git pull» (fail-closed от затирания
   рабочего дерева дома).
2. tmp-каталог: `git init` + `fetch --depth 1 <SELF_MIRROR> main`;
   SHA = `rev-parse FETCH_HEAD`. Сеть/auth-провал → die с подсказкой
   VPN/PAT/URL (формулировка как в corp).
3. SHA == self.rev → «уже свежий», exit 0. `--check`: напечатать
   установленный/доступный SHA и выйти, ничего не меняя.
4. Валидация кандидата (файл `pbx` из FETCH_HEAD): существует, `bash -n`
   проходит, содержит сигнатуру диспетчера pbx (санити от подмены/обрезки —
   надёжнее байтового порога). Провал → die, установленный скрипт не тронут.
5. Бэкап `<путь>.bak`; кандидат во временный файл РЯДОМ с целью (та же ФС),
   `chmod +x`, атомарный `mv -f` (inode swap — безопасно для
   исполняющегося bash-скрипта); запись self.rev.
6. Вывод: `обновлено <sha7-старый> → <sha7-новый>` (первая установка:
   `установлено <sha7>`).

**Тихая проверка** в конце успешного `cmd_snapshot`: если настроен
SELF_MIRROR (self.conf или env) И существует self.rev —
`git ls-remote <SELF_MIRROR> refs/heads/main` (timeout 30);
расхождение → dim-строка «доступно обновление pbx: pbx self-update»
(TTY-only). Best-effort: любой сбой молча игнорируется, exit-код snapshot
не меняется. Дома self.conf не создаётся — проверка не активируется.

**Диагностика**: `collect_diag` (pbx log) дополняется строкой self.rev,
если файл есть (только ДОБАВЛЕНИЕ строки — инвариант Э1).

## 5. Инварианты совместимости (как Э1–Э3)

- Plain-вывод существующих команд не меняется ни на байт; новое в
  snapshot — только TTY-dim; в log/collect_diag — только добавление строк.
- Эмодзи-протокол и fail-closed deliver-guard неприкосновенны.
- Один самодостаточный bash-файл; jq/curl не появляются.
- JSON-схемы status (Э1) и corp (Э3) не трогаются.

## 6. Деградации

- ctx: зеркало недоступно / снимка нет / нет MIRROR → `unknown` с причиной,
  обход остальных продолжается; SRC не git → home-сентинели, корп-часть
  заполняется, вердикт `unknown` (сравнивать нечем — §3.2).
- self-update: см. §4 (die только на сеть/auth/битый кандидат/нет
  SELF_MIRROR; self.rev — best-effort warn).
- Тихая проверка — полностью best-effort.

## 7. Чего НЕ делаем (Э4)

- Заготовка deliver-команды из ctx (ветка+сообщение) — кандидат на потом.
- Автообновление pbx при запуске — отвергнуто (смена поведения посреди
  работы, зависимость каждого запуска от сети).
- Version-строка PBX_VERSION внутри скрипта — self.rev достаточно.
- Обновление self-update-ом чего-либо, кроме файла pbx (README и пр.).
- MR-статусы GitLab API, создание зеркал — по-прежнему вне охвата.

## 8. Тестирование (TDD; все сетевые — на локальных bare-репо file://)

1. Вердикт-логика ctx на фикстуре (дом-SRC + bare-зеркало со снимком):
   `ok` при совпадении; `home_behind_corp` с верным N; `histories_unrelated`
   на несвязанных историях; неоднозначный короткий SHA → строгая трактовка;
   каждая warn-проверка независимо; вердикт = худший уровень; info не
   влияет на вердикт.
2. JSON ctx: python3 -m json.tool; кириллица/кавычки/таб в сабжектах;
   порядок ключей; сентинели unknown-случаев.
3. self-update e2e на bare-зеркале: первая установка; идемпотентность;
   битый кандидат (bash -n fail) → цель не тронута; .bak создан; self.rev
   записан; `--check` ничего не меняет; git-workspace → die; нет
   SELF_MIRROR → die с подсказкой.
4. Тихая проверка: подсказка при расхождении SHA; нет при совпадении;
   сбой ls-remote не меняет exit-код snapshot; plain-вывод snapshot
   не изменился ни на байт.
5. Регресс: полный существующий тест-набор (102) зелёный.
