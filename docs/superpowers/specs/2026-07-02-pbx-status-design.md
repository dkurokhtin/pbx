# pbx Э1 — `pbx status`, манифест pack, апгрейды scan/log (дизайн)

Дата: 2026-07-02. Статус: одобрен пользователем (манифест от pack; транспортная
стратегия «код+состояние через личные GitHub-зеркала» — контекст этапов Э2–Э4).

## 1. Контекст и цель

Этап Э1 дорожной карты «единый инструмент + автоматизация с ИИ»
(Э1 status → Э2 git-транспорт → Э3 обратный поток → Э4 ctx/self-update).

Боль: нет одной команды, показывающей картину по всем проектам — ветка, dirty,
что не упаковано с последнего pack, свежесть архива. ИИ-агенту дома нужен
машиночитаемый срез того же.

Факты разведки (2026-07-02, живые состояния):
- 4 реестровых проекта (rbp/suba/sup/vnd) — git на ext4; 2 WORKSPACE-проекта
  (bot-support-cleaning, smartapp-parking) — НЕ git, на drvfs.
- Краевые случаи существуют в природе: suba — orphan HEAD без коммитов;
  sup — фича-ветка без upstream; rbp — dirty 23 + ahead 2; vnd — dirty 13.
- Перфоманс: git-операция ~1мс (ext4) / 20–80мс (drvfs); полный обход шести
  проектов < 1 сек даже в худшем случае → кэши не нужны (YAGNI).

## 2. Решения и инварианты

- **Манифест от pack** (выбор пользователя): точный дрейф по коммитам,
  задел под Э2/Э3 (deliver будет сверять COMMIT с корп-состоянием).
- **Формат манифеста — bash `KEY=value`** (как все конфиги pbx; jq нет нигде).
- **status — отдельная команда**, list не трогаем (у него устоявшийся
  машинный контракт «голые имена в пайпе»).
- Инварианты совместимости (как в фиче v2): plain-вывод существующих команд
  не меняется; в scan новая информация — только TTY; в log/collect_diag —
  только ДОБАВЛЕНИЕ строк с существующими префиксами блоков; эмодзи-протокол
  и fail-closed guard неприкосновенны; один самодостаточный bash-файл.

## 3. Манифест: `DIST_DIR/<проект>.meta`

`cmd_pack` после успешного создания архива пишет (атомарно: `.tmp` → `mv`):

```bash
# pbx meta: проект <имя>, автогенерация pack
PBX_META_VERSION=1
PACKED_AT=<epoch>          # date +%s в момент упаковки
COMMIT=<sha|->             # git -C SRC rev-parse HEAD; "-" если не git/нет коммитов
BRANCH=<ветка|->           # git branch --show-current; "-" если detached/не git
DIRTY_AT_PACK=<N|->        # число строк git status --porcelain; "-" если не git
```

- Файл НЕ попадает в архив (лежит рядом в DIST_DIR).
- Ошибка записи меты не роняет pack (best-effort: `|| c_warn`), архив важнее.
- Plain-вывод pack не меняется ни на байт; в TTY добавляется dim-строка
  `меta: <sha7> @ <ветка>` после строки размера (TTY-only, как размер).

## 4. `pbx status [проект] [--json]`

Обходит `list_projects` (или один проект). Для каждого собирает:

**SRC:** существует?; git? → ветка (orphan/detached → `HEAD`), dirty N
(`git status --porcelain | wc -l`), upstream (`@{u}` задан?) → ahead/behind
(`git rev-list --left-right --count @{u}...HEAD`), не git → прочерки.

**Архив:** есть? размер (`du -h`), mtime.

**Дрейф от последнего pack:**
- Манифест есть и `COMMIT` валиден (`git cat-file -e COMMIT^{commit}`):
  `unpacked = git rev-list --count COMMIT..HEAD`, плюс текущий dirty.
  Вид дрейфа `exact`.
- Манифеста нет / COMMIT невалиден / SRC не git: эвристика — архив старее
  последнего коммита или dirty>0 → «протух», помечается `~` (вид `heuristic`);
  для не-git SRC дрейф `none` («не git — дрейф неизвестен», только возраст архива).
- Нет архива → «нет архива» (нужен pack).

**REPO:** если каталог из конфига существует локально (актуально на ноуте) —
дополнительная dim-строка: ветка + clean/dirty. Дома, где REPO нет, — ничего.

### Вывод

**TTY** — таблица в стиле `list` (ui_section-шапка), колонки:
`имя(14) · ветка(до 24, обрезка с …) · dirty · архив(размер, возраст) · дрейф`.
Подсветка: дрейф/протухший архив — жёлтым; чисто и упаковано — обычным;
`✓ упаковано` зелёной меткой, `нет архива` — dim.

**non-TTY без `--json`** — та же таблица без ANSI (читаемо в логах агентов).

**`--json`** — плоский массив объектов, ручная сборка + `_json_str`-экранирование.
Схема (контракт для ИИ, фундамент Э4):

```json
[{"name":"vnd","src":"/home/…","src_exists":true,"git":true,
  "branch":"dev","dirty":13,"upstream":"origin/dev","ahead":2,"behind":0,
  "archive":"/…/vnd.tar.gz","archive_exists":true,"archive_mtime":1751450538,
  "archive_size":"3.0M",
  "meta_commit":"abc1234","meta_branch":"dev","meta_packed_at":1751448000,
  "meta_dirty":0,
  "drift":"exact","unpacked_commits":2,"dirty_now":13,"stale":true,
  "repo":"/root/vnd","repo_exists":false}]
```

Сентинели: неизвестная строка → `""`, неизвестное число → `-1`,
`drift ∈ {"exact","heuristic","none"}`. Порядок ключей фиксирован.
`--json` подавляет любой другой вывод на stdout (валидный JSON и ничего больше);
ошибки — только в stderr.

## 5. Апгрейды scan и log

**scan (только TTY):** к строке кандидата `+ <имя> → FIELD=<путь>` добавляется
dim-хвост ` [<ветка>]` (git branch --show-current найденного репо).
Plain-вывод scan байт-в-байт прежний.

**log / collect_diag (обе среды, добавление строк):**
- в блок `[repo]`: строка `[repo]    upstream=<@{u}|—> ahead=<N|—> behind=<N|—>`;
- в блок `[archive]`: при наличии меты строка
  `[archive] meta: commit=<sha> branch=<ветка> packed_at=<ISO>`.
Существующие строки блоков не меняются — парсинг агентов не страдает.

## 6. Меню

Пункт `status  — сводка по проектам` вставляется после `log`. Читающая
команда: выполнение → `menu_pause` → возврат в меню. Нумерация пунктов
сдвигается (`выход` становится 9-м) — тест `test_menu_exit_item`
обновляется соответствующе.

## 7. Чего НЕ делаем (Э1)

- Кэширование (перфоманс < 1 сек — измерено).
- Хеш содержимого архива (отвергнуто пользователем на развилке).
- Обход файлов для не-git SRC (drvfs медленный; дрейф честно «неизвестен»).
- Сетевые операции (fetch для точного behind) — status строго локальна;
  ahead/behind считаются относительно последнего известного remote-состояния.
- MR/PR-статусы — этап Э3.

## 8. Тестирование (TDD, расширение `_tests/test_pbx.sh`)

1. pack пишет мету: поля корректны (git-фикстура), атомарность не проверяем
   (тривиальный mv), plain-вывод pack не изменился (байт-тест уже есть —
   расширить ожидание? НЕТ: meta-строка TTY-only, plain-тест обязан пройти
   без правок).
2. pack на не-git SRC: мета с прочерками, pack не падает.
3. status: дрейф `exact` (фикстура: pack → новый коммит → status видит 1
   unpacked); дрейф `heuristic` (архив без меты); `none` (не-git SRC);
   «нет архива».
4. status: orphan-репо без коммитов (кейс suba) — не падает, ветка `HEAD`,
   COMMIT `-`.
5. status --json: валидный JSON (python3 -c json.load, при отсутствии python3 —
   grep-проверка скобок/ключей), сентинели на месте, stdout не содержит ничего
   кроме JSON.
6. status в пайпе: без ANSI.
7. scan: plain-вывод байт-в-байт прежний (ветка — только TTY).
8. log: новые строки присутствуют, старые не изменены.
9. Меню: обновлённый `test_menu_exit_item` (выход = 9), пункт status
   вызывается и возвращает в меню (пайп-тест: `4\n` затем Enter, q).

## 9. Критерии приёмки

1. `pbx status` дома показывает все 6 проектов с реальными состояниями
   (включая не-git и orphan) быстрее ~2 сек.
2. `pbx status --json | python3 -m json.tool` — валиден.
3. `pbx pack sup` создаёт архив + мету; повторный `pbx status` показывает
   `✓ упаковано`, после нового коммита — `+1 коммит`.
4. Все существующие тесты зелёные без правок (кроме осознанного
   `test_menu_exit_item`); новые тесты зелёные.
5. Файл pbx — один самодостаточный bash-скрипт.

## 10. Этапы реализации (для плана)

1. Манифест в `cmd_pack` (+ тесты 1–2).
2. Сборщик статуса одного проекта (внутренняя функция `status_collect`,
   заполняет переменные ST_*) + дрейф-логика (+ тесты 3–4 через source).
3. `cmd_status`: таблица TTY/plain + `--json` + диспетчер + help (+ тесты 5–6).
4. Апгрейды scan/log (+ тесты 7–8).
5. Меню (+ тест 9) + README (раздел status, упоминание меты).
