# pbx — реестр проектов (паковать/доставлять проекты вне единого WORKSPACE)

- **Дата:** 2026-07-01
- **Статус:** дизайн утверждён, ожидает плана реализации
- **Файл-цель:** `pbx`
- **Предпосылка:** выполнен рефактор «убрать хардкод» (`load_config`, `list_projects`, exclude-билдеры, `forge_push`).

## Проблема

`pbx` находит проекты только как подпапки одного `WORKSPACE` (`/mnt/c/.../Pybotx`). Но проекты
`sup`, `rbp`, `vnd`, `suba` лежат в `/home/dkurokhtin` на этой машине, у них разная структура
(монорепо `sup` = `suba-backend/` + `sup-frontend/`; `rbp` = `RBP-frontend/`; `suba` — сам Vite-фронт).
Рабочий процесс двухмашинный: разработка и `pack` — здесь; архив копируется на рабочий ноут;
`deliver` (ветка/коммит/MR) — там. CLI один и тот же на обеих машинах — **без ssh-оркестрирования**.

Нужно: научить `pbx` работать с проектами, лежащими где угодно, не сломав текущую модель
«WORKSPACE + имя-подпапки» для Pybotx-проектов.

## Решение

Ввести **реестр проектов** — свой на каждой машине. Реестр развязывает имя проекта и путь.

### Реестр

- Каталог: `$PBX_REGISTRY_DIR` (дефолт `${XDG_CONFIG_HOME:-$HOME/.config}/pbx/projects`).
- Один файл на проект: `<имя>.conf`, bash-source (как остальные конфиги). Поля (все необязательны,
  кроме `SRC` для `pack`):

  | Ключ | Назначение |
  |------|-----------|
  | `SRC` | абсолютный путь к корню репо на ЭТОЙ машине — что паковать |
  | `REPO` | абсолютный путь к git-репо для `deliver` (если пусто → `$PROJECTS_ROOT/<имя>`) |
  | `BASE_BRANCH`/`TARGET_BRANCH`/`DEFAULT_ENV`/`FORGE` | как в пер-проектном конфиге |
  | `EXTRA_PACK_EXCLUDES`/`EXTRA_SYNC_EXCLUDES` | доп. исключения |

  Пример `~/.config/pbx/projects/sup.conf` (пакующая машина):
  ```bash
  SRC=/home/dkurokhtin/sup
  TARGET_BRANCH=dev
  FORGE=gitlab
  ```

### Разрешение путей (обратная совместимость)

`load_config <имя>` дополнительно источит реестровый файл и финализирует два пути:
- `SRC` = из реестра, иначе `$WORKSPACE/<имя>` (fallback → Pybotx-проекты работают как раньше).
- `REPO` = из реестра, иначе `$PROJECTS_ROOT/<имя>` (текущая конвенция рабочего ноута `/root/<имя>`).

Слои конфигурации (снизу вверх, верхний побеждает):
```
встроенные дефолты
→ глобальный  $WORKSPACE/.pbx.conf
→ реестр      $PBX_REGISTRY_DIR/<имя>.conf      (новое)
→ в-проекте   <SRC>/.pbx.conf                    (SRC уже разрешён)
→ env PBX_*
→ (после) strip CRLF всех значений, включая SRC/REPO; return 0
```

### `pack` — из `SRC`

Паковать дерево `SRC` (а не `$WORKSPACE/<имя>`). Архив содержит один корневой каталог
`$(basename "$SRC")`; имя архива — по имени проекта: `$DIST_DIR/<имя>.tar.gz`.
Реализация: `tar -C "$(dirname "$SRC")" <excludes> -czf "$out" "$(basename "$SRC")"`.
Существующая в `deliver` логика «если внутри один корневой каталог — зайти в него» это покрывает.

### `deliver` — в `REPO`

Использовать `REPO` вместо `$PROJECTS_ROOT/<имя>`. Остальное без изменений
(checkout base → pull → rsync `--delete` архива → ветка → коммит → `forge_push`).

### Рекурсивные excludes (нужно для этих проектов)

Сейчас pack исключает `node_modules` и `front/node_modules` с префиксом `<project>/` — привязано
к имени и к одному уровню. У `sup` фронт в `sup-frontend/node_modules`, у `rbp` — в
`RBP-frontend/node_modules`. Меняем базовые pack-excludes на **безымянные, любой глубины**
(GNU tar `--exclude` по умолчанию не якорит паттерн → `--exclude=node_modules` исключает
`node_modules` на любом уровне): `node_modules`, `.git`, `.venv`, `__pycache__`, `.claude`,
`CLAUDE.md`, `.pbx.conf`, плюс `*.pyc`. `EXTRA_PACK_EXCLUDES` из конфига по-прежнему добавляются
(тоже без префикса имени). Это заодно снимает зависимость excludes от имени проекта.

### `list_projects` — объединение

Имена = (файлы `$PBX_REGISTRY_DIR/*.conf` без расширения) ∪ (подпапки `$WORKSPACE`, как раньше),
отфильтрованные и `sort -u`. Так `pbx list` показывает и Pybotx-проекты, и sup/rbp/vnd/suba.

### `valid_project`

Проект валиден, если он в реестре ИЛИ существует `$WORKSPACE/<имя>`.

### Новая команда `pbx add <имя> [путь-SRC]`

Создаёт `$PBX_REGISTRY_DIR/<имя>.conf` с `SRC=<путь или $PWD>` (каталог реестра создаётся при
необходимости). Если файл уже есть — не перезаписывать, сообщить (`die`). Печатает путь созданного
файла и подсказку отредактировать при нужде.

## Рабочий процесс (итог)

```
здесь:        pbx add sup /home/dkurokhtin/sup     # однократно завести в реестр
              pbx pack sup                          # → _dist/sup.tar.gz (без node_modules/.git)
              scp _dist/sup.tar.gz work:/root/_dist/ # копирование — вне pbx, как удобно
рабочий ноут: pbx deliver sup feature/... "сообщение"# rsync в /root/sup, ветка/коммит/MR
```

## Границы (что НЕ делаем)

- Никакого ssh/копирования архива средствами `pbx` — топология двухмашинная, шаг копирования ручной.
- `deploy`/`ship` не расширяем (у sup/rbp/vnd/suba нет `scripts/deploy.sh`); они продолжат работать
  через `REPO`/`$PROJECTS_ROOT`, но это вне данного спека.
- Существующие Pybotx-проекты не мигрируем в реестр — работают через WORKSPACE-fallback.
- Формат конфигов и структура команд прежние; правки — аддитивные.

## Критерии приёмки

1. `pbx add foo /path/to/foo` создаёт `$PBX_REGISTRY_DIR/foo.conf` с `SRC=/path/to/foo`;
   повторный `add` не перезатирает, а сообщает об этом.
2. `pbx pack foo` для реестрового проекта пакует дерево из `SRC` (архив содержит `$(basename SRC)/…`),
   исключая `node_modules`/`.git` на любой глубине; `.pbx.conf` не попадает.
3. `pbx pack <pybotx-проект>` (нет в реестре) работает как раньше — из `$WORKSPACE/<имя>`.
4. `load_config foo` даёт `REPO` из реестра, иначе `$PROJECTS_ROOT/foo`; `SRC` из реестра, иначе
   `$WORKSPACE/foo`; env `PBX_*` перебивает; значения очищены от CRLF.
5. Базовый рекурсивный exclude реально исключает `sup-frontend/node_modules`-подобные пути
   (проверка на дереве с вложенным `node_modules`).
6. `pbx list` печатает объединение реестра и подпапок `$WORKSPACE`, без дублей, отсортировано.
7. `deliver` использует `REPO` (реестр) как целевой git-репозиторий.
8. `set -euo pipefail` сохранён; все новые функции set-e/set-u-безопасны; легаси `pack.sh`/`update.sh`
   не тронуты; поведение Pybotx-проектов без реестра не изменилось.

## Открытые вопросы

Нет. Зафиксировано: реестр в `~/.config/pbx/projects/`; единица — весь репозиторий; рабочий ноут —
`/root/<имя>` (REPO нужен редко); команда `pbx add` включена.
