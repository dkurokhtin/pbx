# pbx — убрать хардкод, ввести пер-проектный конфиг

- **Дата:** 2026-07-01
- **Статус:** дизайн утверждён, ожидает плана реализации
- **Файл-цель:** `pbx` (единый CLI: `pack` / `deliver` / `deploy` / `ship`)
- **Окружение:** WSL. Исходники — `/mnt/c/...` (`WORKSPACE`), git-репозитории — `/root` (`PROJECTS_ROOT`).

## Проблема

`pbx` уже вынес глобальные настройки в env-переменные (`PBX_WORKSPACE`, `PBX_PROJECTS_ROOT`,
`PBX_BASE_BRANCH`, `PBX_TARGET_BRANCH`, `PBX_DEFAULT_ENV`), но остаётся хардкод, мешающий
использовать CLI универсально под разные проекты:

1. Список проектов `bot-support-cleaning | smartapp-parking` зашит в шапке скрипта и в `help`
   (и в легаси `pack.sh`). Новый проект требует правки текста.
2. Excludes упаковки (`.venv`, `node_modules`, `.claude`, `CLAUDE.md`, `__pycache__`, `*.pyc`)
   одинаковы для всех проектов и не расширяемы.
3. Excludes rsync при доставке (`.gitlab-ci.yml`, `CLAUDE.md`, `.claude/`) — то же самое.
4. **Ключевое:** `BASE_BRANCH`/`TARGET_BRANCH`/`DEFAULT_ENV` — глобальные. env-переменная одна
   на всех, поэтому нельзя одновременно задать «parking → MR в `dev`, bot-support → MR в `master`».
   В реальном прогоне MR уходил в `dev`, а дефолт скрипта — `master`: расхождение подтверждает,
   что проектам нужны **разные** значения.

## Решение

Пер-проектный конфиг поверх слоёв настроек. Конфиги — обычные `source`-абельные bash-файлы
(`KEY=value` + массивы), т.к. `pbx` сам на bash — парсинг не нужен.

### Слои конфигурации (precedence, снизу вверх — верхний побеждает)

```
1. встроенные дефолты в коде
2. глобальный конфиг     $WORKSPACE/.pbx.conf
3. пер-проектный конфиг  $WORKSPACE/<проект>/.pbx.conf
4. env-переменные PBX_*  (одноразовый override, всегда побеждает)
```

Реализация: `pbx` устанавливает дефолты → `source` глобального конфига (если есть) →
`source` пер-проектного (если есть) → в конце применяет `PBX_*` из окружения, если заданы.
Пер-проектный конфиг читается ПОСЛЕ определения имени проекта в команде.

### Ключи конфига

| Ключ | Дефолт (встроенный) | Назначение |
|------|---------------------|-----------|
| `BASE_BRANCH` | `dev` | от какой ветки ответвляемся |
| `TARGET_BRANCH` | `master` | куда нацелен MR/PR |
| `DEFAULT_ENV` | `dev` | окружение деплоя по умолчанию |
| `FORGE` | `gitlab` | способ создания MR/PR при push (см. ниже) |
| `EXTRA_PACK_EXCLUDES=()` | пусто | доп. исключения при `pack` |
| `EXTRA_SYNC_EXCLUDES=()` | пусто | доп. исключения при rsync в `deliver` |

Соответствие env-override: `PBX_BASE_BRANCH`, `PBX_TARGET_BRANCH`, `PBX_DEFAULT_ENV`, `PBX_FORGE`.
(Массивы excludes переопределяются только через конфиг, не через env.)

### FORGE — универсальность по git-хостам

Сам `git push origin` хост не хардкодит (берёт из `.git/config` репозитория). Разница между
хостами — только в способе создания MR/PR:

- `gitlab` — `git push -o merge_request.create -o merge_request.target=<TARGET> -o merge_request.title=<msg>` (текущее поведение);
- `github` — `git push origin <branch>` затем `gh pr create --base <TARGET> --head <branch> --title <msg>`;
- `none` — просто `git push origin <branch>` без MR/PR.

### Excludes

Базовые excludes остаются в коде как встроенные (не удаляются). Конфиг только **добавляет**:
- `pack`: базовые + `EXTRA_PACK_EXCLUDES`;
- `deliver` rsync: базовые + `EXTRA_SYNC_EXCLUDES`.

`.pbx.conf` автоматически добавляется в оба набора excludes — конфиг никогда не уезжает в
упакованный архив и не синкается в репозиторий.

### Авто-обнаружение проектов

`list_projects()` — все подкаталоги `$WORKSPACE`, кроме служебных (`_dist`, `_source`,
`_backlog`, `.claude`, каталоги на `_` и `.`). Используется в:
- новой команде `pbx list` — печатает найденные проекты;
- `pbx help` — секция «Проекты» формируется динамически (без зашитых имён);
- ошибке `valid_project` — «нет такого проекта; есть: …».

## Границы (что НЕ трогаем)

- `deploy` по-прежнему делегируется в `scripts/deploy.sh` проекта — логику не дублируем.
- Структура команд `pack` / `deliver` / `deploy` / `ship` и их аргументы не меняются.
- URL git-хоста не выносим в переменную — он в `.git/config`; универсальность закрывает `FORGE`.
- Легаси `pack.sh` и `update.sh` оставляем как есть (не ломаем). Возможное удаление/замена
  шимами — отдельным решением позже, вне этого спека.

## Критерии приёмки

1. Без единого конфига `pbx` работает как сейчас (те же дефолты dev/master, те же excludes).
2. Пер-проектный `<проект>/.pbx.conf` с `TARGET_BRANCH=dev` даёт MR в `dev` для этого проекта,
   не влияя на другие.
3. env-переменная `PBX_TARGET_BRANCH=master` перебивает конфиг проекта (одноразовый override).
4. `EXTRA_PACK_EXCLUDES=("dist")` в конфиге исключает `dist/` при `pack`, базовые excludes сохранены.
5. `.pbx.conf` не попадает ни в архив (`pack`), ни в репозиторий (`deliver`).
6. `pbx list` печатает реальные подкаталоги-проекты; в `help` нет зашитых имён проектов.
7. `FORGE=none` пушит ветку без попытки создать MR; `FORGE=github` создаёт PR через `gh`.
8. `set -euo pipefail` сохранён; поведение при «нет изменений» и очистка временной папки не сломаны.

## Открытые вопросы

Нет. Микро-решения зафиксированы: конфиг — `<проект>/.pbx.conf` + общий `$WORKSPACE/.pbx.conf`;
добавляется команда `pbx list`.
