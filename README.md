# pbx — доставка проектов между двумя машинами

Один самодостаточный bash-скрипт: перенести правки проекта с одной машины в
git-репозиторий на другой через личное GitHub-зеркало и открыть MR/PR. Без CI, без
демонов, без зависимостей — только `git`, `rsync` и `bash`.

![демо pbx: snapshot → start → push → deliver](docs/pbx-demo.svg)

## Какую боль это решает

Бывает так, что писать код удобно на одной машине, а создавать merge request можно
только с другой. Например: разработка идёт на домашнем ПК (WSL, доступа к корпоративному
gitlab нет), а MR открывается с рабочего ноутбука, где этот доступ есть. Между ними —
ручной обряд: перенести файлы, не забыть про `.env` и `node_modules`, сделать ветку,
коммит, пуш. Долго и легко ошибиться.

`pbx` сворачивает это в несколько команд, а транспортом служит личное GitHub-зеркало:
дома `pbx start` (ветка от свежего корпа) и `pbx push` (снапшот в зеркало), на машине
с репозиторием — одна команда `pbx deliver`. Реестр проектов на каждой машине помнит,
что где лежит, так что не надо каждый раз печатать пути.

И ещё одна, менее очевидная боль. Если раскладывать в целевой репозиторий весь снимок
(`rsync --delete`), рабочее дерево становится его точной копией: снимок отстал от
целевой ветки — чужая влитая работа молча откатывается. Однажды так затёрлась ролевая
логика из чужого MR. Поэтому `deliver` переносит [только наш дифф](#патч-доставка-от-свежего-корпа-э5),
а перед коммитом всегда работает [страховка](#страховка-deliver-guard).

## Как устроен поток

```mermaid
flowchart LR
    subgraph host["🖥️ ноут: машина с корп-репо"]
        snap["pbx snapshot"]
        deliver["pbx deliver:<br/>dev → pull → наш дифф → guard → коммит"] --> mr["MR в dev"]
    end
    subgraph mirror["☁️ личное GitHub-зеркало"]
        cdev["corp-dev"]
        mst["pbx/state"]
        mbr["ветка задачи (снапшот)"]
    end
    subgraph home["🏠 дом: SRC"]
        start["pbx start: ветка от corp-dev"] --> edit["правки"] --> push["pbx push &lt;проект&gt; &lt;ветка&gt;"]
        ctx["pbx ctx / pbx corp: вердикт готовности"]
    end
    snap --> cdev
    snap --> mst
    cdev --> start
    mst -.->|"читается дома"| ctx
    push --> mbr
    mbr --> deliver
```

1. **Ноут:** `pbx snapshot` — снимок корп-репо в `pbx/state` и корп-`dev` веткой `corp-dev` зеркала.
2. **Дом:** `pbx start <проект> <ветка>` — ветка в SRC от `corp-dev` (чистое дерево).
3. **Дом:** правки → `pbx ctx <проект>` → `pbx push <проект> <ветка>`.
4. **Ноут:** `pbx deliver <проект> feature/<ТИКЕТ>-<slug> "<сообщение>" --from <ветка>` —
   на свежий `dev` ложится только дифф «общий предок → снапшот»; не лёг — откат без коммита.

Запасной режим один: `pbx deliver … --mirror` раскладывает ветку зеркала целиком
через `rsync --delete` — только когда дом гарантированно равен корпу.

## Команды

    pbx snapshot [имя]                                НОУТ: снимок корп-состояния → pbx/state + корп-dev → corp-dev зеркала
    pbx start   <имя> <ветка>                         ДОМ: новая задача — ветка в SRC от corp-dev зеркала
    pbx ctx     [имя] [--json]                        ДОМ: вердикт готовности к доставке — сравнение дом↔корп по снимку (ok/warn/danger/unknown, страховка SUP-2603)
    pbx push    <имя> [ветка]                         ДОМ: снапшот рабочего дерева → ветка зеркала (MIRROR)
    pbx deliver <имя> <ветка> <сообщение> [--from <ветка зеркала>] [--base <sha>] [--yes] [--mirror]
                                                      НОУТ: наш дифф поверх свежего dev → ветка, коммит, MR/PR
    pbx corp    [имя] [--json]                        ДОМ: показать снимок корп-состояния из зеркала
    pbx status  [имя] [--json]                        сводка: ветка, правки, последний push и отставание от SRC
    pbx log     [имя]                                 диагностика для ИИ-агента (stdout + лог-файл)
    pbx add     <имя> [путь]                          завести проект в реестр (SRC=путь|$PWD)
    pbx scan    (--repo|--src) [каталог] [--dry-run]  заполнить реестр из найденных репо
    pbx list                                          показать проекты (реестр ∪ WORKSPACE)
    pbx self-update [--check]                         НОУТ: обновить pbx из личного зеркала инструмента (SELF_MIRROR в ~/.config/pbx/self.conf; ветка зеркала: SELF_BRANCH=/PBX_SELF_BRANCH, дефолт main); --check — только проверить
    pbx help

`--patch` у `deliver` принимается для совместимости со старыми инструкциями — это и
есть режим по умолчанию.

## Интерактивное меню

Голый `pbx` в терминале открывает меню: стрелки ↑/↓ (или j/k, или цифры),
Enter — выбрать, Esc/q — отмена. Пункты идут в порядке потока:
snapshot (ноут) → start → ctx → push (дом) → deliver (ноут), дальше corp,
status, log, list.

- **start** спросит проект и ветку (подставит `fix/`) → `pbx start`.
- **deliver** спросит проект, ветку (подставит `feature/`), сообщение и ветку
  зеркала для `--from` (пусто — та же) → `pbx deliver … --from …`
  со всеми страховками (guard остаётся).
- snapshot и corp проходят сразу по всем проектам с MIRROR.

Меню включается только когда stdin и stdout — терминал. Скрипты и ИИ-агенты
ничего не заметят: `pbx` без аргументов в пайпе печатает справку.
Отключить насовсем: `PBX_NO_MENU=1`.

Цвет гейтирован: в пайпе/редиректе вывод — чистый plain-текст
(соблюдается `NO_COLOR`, `TERM=dumb`).

## Статус проектов

![демо pbx status](docs/demo-status.svg)

`pbx status` — сводка по всем проектам: ветка, незакоммиченные правки, когда был
последний `push` и отстаёт ли снапшот в зеркале от SRC («✓ в зеркале» /
«+N коммит., M файл. правок после push» / «не пушилось»). `pbx status <проект>` — по
одному, `pbx status --json` — машиночитаемо (для ИИ-агентов и скриптов).

`push` пишет манифест `_dist/<проект>.meta` (ветка и коммит снапшота, исходный
коммит SRC, время) — по нему `status`, `ctx` и `list` считают отставание.

## Транспорт через личное GitHub-зеркало (Э2)

Дома `pbx push <проект> [ветка]` — снапшот рабочего дерева SRC (включая
незакоммиченное) уезжает коммитом в ветку личного зеркала (ключ `MIRROR=` в
реестре). Снапшот уважает `.gitignore` SRC — gitignored-файлы (например `.env`)
в зеркало НЕ уезжают; плюс фиксированные исключения (`node_modules`, `.git`,
`.venv`, кэши, контекст агента без `AGENT_FILES=1`, `EXTRA_PACK_EXCLUDES`).
История снапшотов в зеркале сохраняется (parent-chain), `--force` не используется.

Запасной `pbx deliver <проект> <ветка> <сообщение> --mirror` берёт ветку зеркала
целиком и раскладывает её в REPO через `rsync --delete` (тот же guard). Нужен,
только когда дом гарантированно равен корпу; штатно — патч-доставка ниже.

Auth ноута (root): рекомендован HTTPS + fine-grained PAT (скоуп — только
зеркала, Contents Read/Write, срок ~90 дней) через `git credential-cache`
или `~/.git-credentials` (600). Токен НЕ вписывать в URL реестра. При
отсутствии/протухании токена pbx падает с понятной ошибкой, не виснет.

## Обратный поток: состояние корп-репозиториев (Э3)

![демо pbx snapshot и pbx corp](docs/demo-corp.svg)

Дом не видит корп-GitLab. Чтобы планировать доставку по фактам (страховка от
«устаревший снимок молча откатывает чужую работу», класс SUP-2603):

- **Ноут, конец дня:** `pbx snapshot` — снимает состояние всех корп-реп
  (ветки, лог dev, ahead/behind доставленных веток) в 4 маленьких файла и
  коммитит их в служебную ветку `pbx/state` личного зеркала (MIRROR).
  Git-объекты корп-истории в эту ветку НЕ уезжают — только текстовые метаданные
  (sha, сабжекты, имена веток).
- **Дом, перед доставкой:** `pbx corp [проект]` — показывает снимок: возраст,
  верхушку dev, доставленные ветки с ahead/behind. Для ИИ-агента:
  `pbx corp <проект> --json`.
- **Дом, автовердикт (Э4):** `pbx ctx [проект]` — та же страховка от SUP-2603,
  но уже не сырой снимок, а готовый вердикт `ok/warn/danger/unknown` с
  причинами (дрейф от dev, грязный REPO, протухший снимок, недоставленные
  ветки). `pbx ctx --json` — для ИИ-агента. «Push отстаёт» показывается только
  когда дерево SRC отличается от корп-tip, то есть дома есть что доставлять.

Auth — тот же, что для транспорта (SSH дома, HTTPS+PAT на ноуте, см. выше).
Снимок старше 24 ч помечается протухшим. Без VPN на ноуте снимок делается по
последним известным remote-refs с пометкой `fetch_ok=false`.

## Патч-доставка от свежего корпа (Э5)

Режим `deliver` по умолчанию: переносится **только наш дифф**, чужая влитая работа
и файлы DevOps не трогаются — патч их просто не содержит.

- **Ноут:** `pbx snapshot` кроме снимка выкладывает корп-`dev` в зеркало
  веткой `corp-dev` (`corp-<BASE_BRANCH>`). Это осознанно тащит корп-историю
  в личное зеркало; выключается `CORP_SYNC=0` в conf проекта. Ветка
  `pbx/state` по-прежнему без корп-родителей.
- **Дом:** `pbx start <проект> <ветка>` — ветка в SRC от `corp-dev` зеркала
  (нужно чистое дерево). История дома совпадает с корпом по SHA, `pbx ctx`
  даёт точный вердикт. Дальше правки и `pbx push <проект> <ветка>`.
- **Ноут:** одна команда —

      pbx deliver <проект> feature/SUBA-123-x "Сообщение" --from <домашняя ветка>

  `checkout dev` → `pull` → fetch ветки зеркала → дифф «база → снапшот»
  (база — общий предок с `dev`, то есть коммит, от которого делали
  `pbx start`) → `git apply --index` на свежий `dev` → guard → commit → MR.
  `--from` по умолчанию совпадает с именем ветки доставки.

Если патч не лёг (эти места в корпе уже менялись), ничего не коммитится:
ветка удаляется, REPO остаётся на чистом `dev`. Ветку, начатую не через
`pbx start` (нет общей истории с корпом), можно доставить с явной базой
`--base <sha>` — коммит, от которого считать наш дифф.

### Быстрый snapshot и сетевые повторы (Э7)

- `pbx snapshot` не создаёт новый коммит в `pbx/state`, если корп-состояние
  не изменилось с прошлого снимка (сравнение без метки времени) и прошлому
  снимку меньше 12 ч (`PBX_SNAPSHOT_REFRESH_SEC`, половина срока «снимок
  протух» у ctx). Принудительно — `PBX_SNAPSHOT_FORCE=1`.
- `corp-dev` не пушится, если в зеркале уже тот же SHA (сверка `ls-remote`).
- Сетевые операции с зеркалом (`start`, `deliver`, сверки snapshot)
  повторяются до `PBX_NET_TRIES` (3) раз по `PBX_NET_TIMEOUT` (45) с: GitHub
  временами подвисает. `pbx start` различает «ветки нет» и «зеркало не ответило».

### Предстарт deliver (Э8)

Перед доставкой `deliver` проверяет корп-репо: если оно не на `BASE_BRANCH` —
явно переключает (сообщает об этом); если в нём незакоммиченные правки
(остаток прерванной доставки) или ветка доставки уже существует — останавливается
до любых действий и подсказывает команду. После пуша MR репо возвращается на
`BASE_BRANCH`, чтобы следующая доставка и snapshot стартовали с базовой ветки.

### Без архивов (Э9)

Первый транспорт pbx — `pbx pack` в tar.gz с ручным переносом и раскладкой через
`rsync --delete` — удалён: доставка идёт только через зеркало. `pbx pack` и
`deliver` с путём к архиву завершаются понятной ошибкой с подсказкой.

## Рабочий процесс

    # ноут (машина с репозиторием)
    pbx snapshot sup                   # корп-dev → corp-dev зеркала + снимок pbx/state

    # дом (рабочая машина)
    pbx add sup /home/me/sup           # один раз
    pbx start sup fix/x                # ветка от corp-dev
    # ... правки ...
    pbx ctx sup                        # вердикт ok/warn/danger
    pbx push sup fix/x                 # снапшот → ветка fix/x зеркала

    # ноут
    pbx deliver sup feature/PROJ-123-fix "Починить X" --from fix/x

## Страховка (deliver-guard)

![демо deliver: guard и откат без коммита](docs/demo-guard.svg)

Перед коммитом `deliver` показывает, что именно уедет в MR:

- `git diff --cached --stat` — полный список файлов;
- отдельно выделяет **удаляемые** файлы: это удаления из твоей ветки зеркала
  (проверь, что намеренные); в `--mirror` — частый признак доставки от
  устаревшего снимка;
- просит подтверждения. Пропустить — флагом `--yes` или `PBX_ASSUME_YES=1`.

Отказ (`n`) или прерывание без подтверждения откатывают всё сами: ветка
доставки удаляется, репо остаётся на чистом `BASE_BRANCH` — патч всегда можно
снять из зеркала заново. Так же откатывается патч, который не лёг на свежий
`dev` (эти строки в корпе уже меняли). В `--mirror` при отказе репо остаётся на
ветке доставки для разбора, команда отката печатается.

В неинтерактивном режиме без подтверждения доставка прерывается (fail-closed) — лучше
остановиться, чем молча снести чужую работу. Правило простое: **всегда смотри вкладку
Changes перед мержем**; удаления файлов, которых ты не трогал, — красный флаг.

## Диагностика (pbx log)

`pbx log <имя>` собирает всё, что нужно, чтобы разобраться в сбое доставки, и пишет это
в stdout и в `_dist/pbx-<имя>.log` (если каталог недоступен — в `$HOME`):

- версия самого `pbx`, окружение и версии инструментов (git/rsync/tar/gh);
- как `pbx` разрешил конфиг проекта (SRC/REPO/MIRROR/ветки/FORGE);
- git-состояние целевого репо (ветка, статус, последние коммиты);
- последний push из манифеста (ветка, снапшот, исходный коммит, время).

Тот же отчёт `pbx` **сам** дописывает в лог-файл при любой ошибке — чтобы у ИИ-агента,
который потом будет разбирать сбой, сразу был весь контекст.

## Реестр проектов

Проекты описываются в `$PBX_REGISTRY_DIR` (дефолт `~/.config/pbx/projects/`), один файл
`<имя>.conf` на проект — свой на каждой машине:

    SRC=/home/me/sup          # исходники на ЭТОЙ машине (дом)
    REPO=/root/sup            # куда доставлять (ноут; иначе $PROJECTS_ROOT/<имя>)
    MIRROR=git@github.com:me/sup-mirror.git   # личное зеркало (обе машины)
    TARGET_BRANCH=dev         # + BASE_BRANCH / FORGE / AGENT_FILES / CORP_SYNC / EXTRA_*

Нет в реестре — fallback: `SRC=$WORKSPACE/<имя>`, `REPO=$PROJECTS_ROOT/<имя>`.
`EXTRA_PACK_EXCLUDES` — доп. исключения снапшота push (имя ключа историческое,
оставлено ради совместимости реестров), `EXTRA_SYNC_EXCLUDES` — синка `--mirror`.

## Слои настроек (побеждает верхний)

    встроенные дефолты → $WORKSPACE/.pbx.conf → реестр <имя>.conf → <SRC>/.pbx.conf → env PBX_*
